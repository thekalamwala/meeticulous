## HIGH

This file exists to feed AI answers → GEO surfaces cite dead plan names and wrong prices. Also missing: 4 newer /lp comparisons, /for pages, /features, /explore, /blog.
   Fix: rewrite `client/public/llms.txt`; source pricing line from `data/plans.js` wording.

2. **sitemap-pages.xml missing ~28 live URLs.** Live child has 28 URLs; absent: `/lp/setmore-alternative`, `/lp/acuity-alternative`, `/lp/simplybook-alternative`, `/lp/zoho-bookings-alternative`, all 10 `/features/*`, `/help/docs` + every help-doc slug, `/wall-of-love`. All are prerendered/public but never announced to crawlers.
   Fix: extend `STATIC_ROUTES` in `server/services/sitemapService.js` (import feature slugs list server-side or hardcode; help slugs likewise).

3. **SPA fallback = prerendered homepage → wrong canonical in initial HTML everywhere else.** `prerender.mjs` overwrites `dist/index.html` with the rendered homepage (title, full meta, JSON-LD, `canonical=https://meeticulous.com/`). Vercel serves that file for every route without its own prerender: `/wall-of-love`, `/services/:profession`, and — critically — host/service profiles for **Googlebot**, which is deliberately NOT in the bot-proxy UA list. Google's raw-HTML pass sees `canonical=/` + homepage schema on thousands of profile URLs; correct tags only appear after JS render. Canonical-conflict / duplicate-homepage risk at scale.
   Fix options (pick one): (a) write prerendered homepage to `dist/index.html` AND keep a clean neutral shell (no canonical, no JSON-LD) as the SPA fallback via a separate rewrite target; (b) add Googlebot to `BOT_UA_RE` for the 1–2-segment profile routes only; (c) strip canonical+JSON-LD from the fallback copy post-prerender.

4. **Unknown username → HTTP 200 (soft-404), human and bot.** `zzz-no-such-host-xyz` returns 200 homepage shell. Dead/renamed hosts stay indexed forever, crawl budget burns. Middleware already calls `/api/username/resolve` — on `found:false` it can return 404/410 instead of falling through.

5. **www.meeticulous.com serves 200, no redirect to apex.** Duplicate-host split; canonicals mitigate but the 308 www→apex is one Vercel domain-settings toggle. (Code untouched.)
